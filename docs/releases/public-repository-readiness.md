# 公开仓库就绪审计

**目标版本：** `v0.1.0-beta.1`

## 发布边界

公开仓库由当前私有开发仓库的受审源码快照新建，不继承私有 `.git`、旧提交祖先或远程配置。

公开源码快照包含：

- 生产应用源码、锁定依赖和第三方源码
- 公共测试、合成测试资料和稳定协议
- MIT `LICENSE`、README、安全政策、贡献指南和更新记录
- 公开发布说明和生产构建所需的最小脚本
- 只读 GitHub Actions CI

公开源码快照不包含：

- 私有产品规划、架构门禁和实现过程记录
- 原始 Spike/QA/虚拟机/实机证据
- 特定主机脚本、绝对路径、账号或机器标识
- `.git`、`target`、`node_modules`、数据库、备份、日志、截图或本地发布暂存

## 历史策略

公开 staging 仓库使用 `git init -b main` 创建全新历史。私有开发仓库继续保留完整历史和证据，不做 history rewrite、filter、reset、stash 或清理。

最终公开仓库路径、首个提交 SHA、提交数量、旧历史可达性和安全扫描结果会写入发布清单，并在本批最终结果中报告。

## 发布门禁

- 项目许可证为 MIT，版权身份为 `JasonYang-GJ`。
- 只有在 Owner 明确授权且最终公开安全审计通过后，才可配置公开 remote 并 Push。
- 创建 Git Tag 和 GitHub Release 需要单独授权；源码仓库发布不自动包含这些操作。
- 最终可执行文件必须只从受审公开仓库源码重建。
- 发布包只包含可执行文件、LICENSE、第三方声明、发布说明和清单。
- 可执行文件必须不含 PDB、私有日志、测试数据库、真实用户数据或私有证据。
